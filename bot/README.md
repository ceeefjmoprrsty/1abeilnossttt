# Бот записи на маникюр (Telegram)

Бот для частного мастера: клиент выбирает услугу, дату, время, оставляет имя,
фамилию и телефон, затем подтверждает запись. Все записи хранятся в SQLite
(`bookings.db`).

## Установка и запуск

```bash
pip install -r requirements.txt
python main.py
```

## Настройка (файл `config.py`)

| Параметр | Описание |
|---|---|
| `BOT_TOKEN` | Токен бота от @BotFather |
| `ADMIN_IDS` | Ваш Telegram ID (узнать: написать боту @userinfobot) — для уведомлений о записях и команд мастера |
| `MASTER_NAME`, `MASTER_CONTACT` | Имя и контакт мастера в приветствии |
| `PRICES` | Прайс-лист: услуга → цена в ₽ (кнопки строятся из него) |
| `WORK_START_HOUR` / `WORK_END_HOUR` / `SLOT_HOURS` | Рабочие часы и длительность слота (по умолчанию 10:00–19:00, шаг 2 ч) |
| `MAX_DAYS_AHEAD` | На сколько дней вперёд доступна запись |
| `PROXY_URL` | Прокси, если Telegram недоступен напрямую, напр. `"socks5://127.0.0.1:1080"` (в РФ часто обязателен) |

## Сценарий записи

Вся анкета клиента — это **одно сообщение**, которое бот редактирует после
каждого выбора. Никаких лишних сообщений в чате не появляется.

Карточка выглядит так и дозаполняется по шагам:

```
💅 Запись к мастеру Мастер (@kylonil)

1. Услуга:  Маникюр + покрытие гель-лак — 2500 ₽ ✅
2. Дата:    5 декабря, суббота ✅
3. Время:   14:00 ✅
4. Имя:     —
5. Телефон: —

4️⃣ Напишите имя и фамилию (текстом):
```

1. `/start` → кнопка «💅 Записаться» (это же сообщение превращается в карточку)
2. **Услуга** — кнопки из прайса
3. **Дата** — календарь-сетка: 7 столбцов (Пн–Вс) × 4–5 строк, на кнопках
   только число месяца. Недоступные дни (прошедшие и полностью занятые)
   показаны как `·`
4. **Время** — только свободные слоты
5. **Имя и фамилия** — текстом
6. **Телефон** — текстом, с валидацией формата
7. **Подтверждение** — те же кнопки в этом же сообщении

После подтверждения карточка переписывается в итог записи, а мастер (если
прописан `ADMIN_IDS`) получает уведомление с телефоном клиента.

## Надёжность

- Состояние анкеты (FSM) хранится в SQLite (`fsm_storage.db`) и **переживает
  перезапуск бота**: клиент может нажать кнопку в карточке даже после рестарта.
- Нажатие устаревшей кнопки (например, из уже завершённой записи) не «повисает» —
  бот подскажет начать заново через `/start`.
- Запускайте **только один экземпляр** бота (`python main.py`). Два процесса с
  одним токеном забирают апдейты по очереди и поведение становится непредсказуемым.

## Команды

- `/start` — начать запись
- `/help` — прайс-лист
- `/cancel` — отменить текущую запись
- `/bookings` — (мастер) записи на сегодня
- `/all` — (мастер) все записи
